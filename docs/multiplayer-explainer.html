Real-Time Telegram Multiplayer & Lifecycle Engine

A zero-JVM, pure native JavaScript 1v1 combat architecture inside Telegram Mini Apps featuring inline challenge matchmaking, 60-second lobby timeouts, real-time input relays, 60-second disconnect forfeit autowins, and local group-isolated leaderboards.

1. Executive Summary

Immortal Combat's multiplayer layer bridges two Telegram users into a synchronized 2D arcade combat arena. It operates seamlessly across direct messages (DMs) and group chats via Telegram's Inline Query API and Telegram Mini App (TMA) deep links.

Guaranteed Core Behaviors:
  • Inline Challenge: A user invokes @BotName in a DM or group to drop an instant challenge card with a 60-second join window.
  • 60s Lobby Timeout: If the challenged player does not join within 60 seconds, the match state transitions to CANCELLED and the creator is notified.
  • Zero-Latency Relay: Player inputs (8-way D-pad, punch, kick, block) are relayed between players over full-duplex WebSockets.
  • 60s Forfeit Autowin: If an active player closes the Mini App or loses connection, a 60-second grace timer begins. If they fail to reconnect, their opponent is instantly awarded an AUTOWIN.
  • Dual-Exit Abort: If the waiting player ALSO disconnects before the 60s expires, the match is marked ABANDONED and neither player is awarded a win.
  • Local Group Leaderboards: Standings (Wins, Losses, Total Battles, Win Rate) are strictly isolated per chat/group. Matches fought in Group A never taint the standings of Group B.

2. System Topology & Subsystems

The multiplayer stack is composed of four decoupled subsystems cooperating over HTTP and WebSockets:

Telegram Bot Gateway (aiogram 3.x)

Handles InlineQuery requests, /challenge commands, /leaderboard inquiries, and TMA deep link launches via startapp=challenge_<id>.

File: bot.py
Real-Time Coordinator (aiohttp)

Manages in-memory match rooms, WebSocket routing, join countdowns, heartbeat pings, 60-second disconnect grace tasks, and input broadcasting.

File: server/multiplayer.py
Local Persistence Layer (SQLite WAL)

Atomic transactions tracking match records and group-isolated leaderboard statistics. Calculates win rates and tracks last active timestamps.

File: server/db.py
TMA Frontend Client (ES6 WebApp)

Manages the 8-way joystick, 6-button combat cluster, HUD status indicators, 60-second countdown bars, forfeit banners, and J2ME LCDUI engine hooks.

Files: player/js/network.js, player/js/main.js

3. Challenge Creation & 60-Second Lobby Expiration

When a player triggers an inline challenge, a pre-allocated match room is initialized with an explicit expires_at = now() + 60s deadline. If an opponent taps the button in time, the match transitions to ACTIVE; otherwise, the server cancels it automatically.

4. Zero-Latency Combat Input Synchronization

During active combat, both clients run the 1:1 J2ME simulation locally. When Player 1 inputs an attack or movement command, it is executed locally with 0ms visual latency, while a compact JSON payload is forwarded through the WebSocket coordinator to control Fighter C on Player 2's screen.

5. Disconnection Grace Period & Forfeit Autowin Protocol

The state machine strictly enforces the user requirement: when an opponent exits an active match, the remaining player waits for 1 minute for an autowin. If the remaining player exits too during that minute, no win is awarded to anyone.

6. Local Group-Isolated Leaderboard

Leaderboards are bound strictly to the chat_id where the challenge was issued or played. This ensures that office groups, friend circles, or community chats maintain independent competitive standings.

Field Type Description
chat_id TEXT (Primary Key 1) Unique Telegram Group ID (e.g. -1001928374) or DM channel.
user_id TEXT (Primary Key 2) Telegram user ID of the fighter.
first_name TEXT Display name of the fighter in Telegram.
wins INTEGER Total matches won by knockout or opponent forfeit.
losses INTEGER Total matches lost by knockout or forfeit timeout.
draws INTEGER Matches abandoned when both players disconnected.
games_played INTEGER Total matches contested (wins + losses + draws).
win_rate REAL (%) Calculated dynamically: round((wins / games_played) * 100, 1).
Telegram Chat Formatting: When a user issues /leaderboard, the bot queries SQLite and responds with a formatted standings table topped with gold, silver, and bronze medals (🥇, 🥈, 🥉), player names, record breakdowns (e.g. 5W / 1L), and win percentages.

7. Edge Cases & Fail-Safe Mitigations

Creator closes lobby before opponent joins
Server detects active sockets == 0, cancels the 60s background task, and sets match status to CANCELLED with reason CREATOR_LEFT.
Creator tries to accept their own challenge
join_match validates creator_id != user_id. If the creator taps the button in the group, they are re-attached as Player 1 without spawning a phantom opponent.
Both players close the Mini App simultaneously
When the second socket closes during the 60s grace countdown, the server detects zero remaining sockets, cancels the forfeit timer, and records BOTH_DISCONNECTED. Neither player receives a win.
Transient mobile network loss (< 60s)
The client automatically reconnects with its stored match ID and user ID. The server cancels the forfeit timer and broadcasts opponent_reconnected, resuming the match smoothly.
